MySQL 5.7 下载安装全流程：从踩坑到一键部署

写在前面

MySQL 5.7 现场安装看着简单，实际上每年都有人栽在同一个地方：解压完就去启动服务，结果服务死活起不来，翻开日志全是 failed to set datadir、Table 'mysql.user' doesn't exist。我自己也踩过一整轮，从排查到做出一套”拷进去右键就能装”的脚本，把坑全填了。这篇把下载、安装、初始化、排障一次讲清楚，照着做基本不会卡。

一、先搞懂为什么会启动失败

动手之前先记住三个高频坑，后面所有步骤都是围绕它们设计的：

坑 现象 根本原因
没有 my.ini 报 Can't change dir to ...\data 或 failed to set datadir 解压版不带配置文件，mysqld 用内置默认 datadir，路径根本不存在
datadir 指错 服务找不到数据目录 服务注册时没带 --defaults-file，mysqld 不知道配置文件在哪
没初始化 报 Table 'mysql.user' doesn't exist 光解压不初始化，mysql、sys 这些系统库压根没建出来

一句话：解压 ≠ 安装，必须先有配置、再初始化、最后注册服务。

二、方案选择：zip 版还是 MSI 版

对比 MSI 安装器 zip 免安装版（本文方案）
网络依赖 部分步骤要联网拉组件 完全离线，拷进去就装
可复现性 图形向导一步步点，容易漏 脚本固定，每台机器结果一致
配置文件 分散在 ProgramData my.ini 就放 MySQL 根目录
服务参数 向导隐式处理 显式带 --defaults-file，datadir 不会跑偏
排障 难定位 步骤、日志、验证都在脚本里

现场、内网、批量部署，优先 zip 版。

三、下载

MySQL 5.7 已经停止官方维护（EOL），官网首页默认推 8.x，得去归档页下：

  1. 打开官方归档：https://downloads.mysql.com/archives/community/
  2. Product Version 选 5.7.36（5.7 最后一个版本）
  3. Operating System 选 Microsoft Windows
  4. 下载 mysql-5.7.36-winx64.zip（64 位免安装版）
  5. 现场通常没外网，务必在办公室先下好，用 U 盘拷过去

挑 5.7.36 而不是 8.x：老业务系统大量依赖 5.7 的认证插件和 SQL 语法，升级成本远高于用最后一个稳定版。

四、安装前准备

项 要求 说明
管理员账号 必须 装服务、写目录都要管理员权限
VC++ 运行库 建议先装 Visual C++ Redistributable 2013 x64，缺了初始化会报 MSVCR120.dll 找不到
端口 3306 确认空闲 被占用就换端口，或先停掉占用程序
路径 纯英文、无空格 推荐 C:\mysql-5.7.36-winx64，空格路径在 MySQL 生态里坑多

五、安装步骤

1. 解压

解压到纯英文路径，例如 C:\mysql-5.7.36-winx64，里面应有 bin\、docs\、share\ 等目录。

注意：解压出来默认没有 data 目录、没有 my.ini，这是正常的，接下来生成。

2. 写 my.ini

在 MySQL 根目录建一个 my.ini（注意是 ANSI/UTF-8 无 BOM 编码）：

两个关键点：

  • basedir / datadir 必须是你要放的真实路径，路径用正斜杠 /（反斜杠在 ini 里容易被当转义）
  • datadir 指向的目录可以先不存在，初始化时会自动建；但必须是空目录或全新目录

3. 初始化（最关键的一步）

用管理员打开命令行，切到 MySQL 根目录执行：

  • --defaults-file 必须是 mysqld 后面的第一个参数，否则不生效
  • --initialize-insecure 表示 root 用空密码，省去去日志里翻随机密码的麻烦（装完立刻改密码即可）
  • 看到程序正常退出、data 目录下出现 ibdata1、ib_logfile* 和 mysql\ 目录，就说明初始化成功

如果这里报 Table 'mysql.user' doesn't exist 之外的错，先看屏幕日志，多半是路径写错或目录非空。

同样，--defaults-file 放在最前面。服务名 MySql57 可以自己改。

能打印出版本号和正确的数据目录，就装好了。再看系统库是否齐全：

应能看到 information_schema、mysql、performance_schema、sys 四个库。

六、装完立刻做的两件事

1）改 root 空密码

2）建业务库和应用账号（别让应用直接用 root）

应用和数据库不在同一台机器时，把账号的 localhost 改成应用服务器 IP 或 %，并放行防火墙 3306。

七、常见故障排查

现象 原因 处理

八、日常运维与卸载

操作 命令
启动 / 停止 net start MySql57 / net stop MySql57
改配置 改 my.ini 后重启服务
卸载服务（保留数据） bin\mysqld.exe --remove MySql57

结语

MySQL 5.7 现场安装其实就三件事：写对 my.ini、执行初始化、注册服务时带 --defaults-file。把这三点记住，无论内网离线还是批量部署，都能一遍过。我把这套流程固化成了一键脚本（生成配置 → 初始化 → 装服务 → 启动 → 验证），现场拷进去右键管理员运行即可，需要的话可以按本文逻辑自行改写。

ESP32-P4 采集 NE555 波形，今天就能做

ESP32-P4 采集 NE555 波形 · 今天就能做

目标只有一个：电脑上看到 12V 方波。看到波形 = NE555 模块正常起振 = Step 1 通过。
适用：微雪 ESP32-P4-WIFI6-DEV-KIT（你手上这块）+ 你的 NE555 集成模块。
今天不碰任何高压。

0. 先记住两句话

  1. 12V 绝对不能直接进 GPIO —— 必须经分压降到 3V 左右。
  2. 必须共地 —— NE555 的 GND 和 P4 的 GND 连在一起，否则读数乱跳或全是 0。

1. 接线（3 根线 + 2 个电阻）

物料

元件 值 你手头
电阻 R1 10 kΩ 有
电阻 R2 3.3 kΩ 没有就用 4.7 kΩ（降到 3.8V，仍在安全内）或 2×6.8k 并联
杜邦线 4 根 有

接法

  • GPIO23 在 40pin 排针左列第 4 脚（从板子边缘数，认丝印 GPIO23）
  • GND 任选板上标 GND 的黑脚
  • 分压节点 = 12V × 3.3 / 13.3 = 2.98V，安全
  • 若用 4.7k：12 × 4.7/14.7 = 3.84V —— 超过 3.3V 了，不行。必须 ≤3.3k。
    没有 3.3k 就用 3.3k 或 2.2k（2.2k → 2.16V，也安全），或者 10k 高边换成 15k（15k+4.7k → 2.86V）。

推荐组合（挑一个）

  • R1=10k, R2=3.3k → 2.98V ✅ 最佳
  • R1=10k, R2=2.2k → 2.16V ✅ 安全，幅度小一点
  • R1=15k, R2=4.7k → 2.86V ✅ 手头有 4.7k 时用这个

接完先用万用表验一次（30 秒）

万用表 DCV 20V 档，红表笔接分压节点（GPIO23 那点），黑表笔接 GND：

读数 判断
1.5~3.2V 之间某值 ✅ 安全，可以上电
> 3.3V ❌ 停！电阻接反或阻值不对
0V 检查 NE555 是否供电、OUT 是否有输出

串口采集与示波器上位机开发实录：ESP32-P4 + PyQt6

07 · 串口采集与示波器上位机开发实录

2026-11-18 · 用 ESP32-P4 采集 NE555 方波，PyQt6 自研示波器，当天从零到全链路跑通。
本文是代码 + 每个坑的根因分析，不是操作教程（操作见 《06 · ESP32-P4 采集 NE555 波形》）。

1. 系统架构

带宽账本（为什么必须 921600）：2000 行/s × 每行约 13 字节 ≈ 24 kB/s，
115200 串口只扛得住 ~11.5 kB/s，会丢数据；921600 ≈ 92 kB/s，余量近 4 倍。

2. 下位机固件（ESP-IDF 5.5.2，main/test_ne555.c 全文）

三个设计决策的理由：

决策 理由
adc_oneshot 循环，不用 adc_continuous(DMA) 只要”看到波形”，15 行代码 vs 一整套回调+解析；2000Hz 单次读取绰绰有余。以后做 MHz 级局放再换 DMA
esp_rom_delay_us 忙等对齐节拍 不用 vTaskDelay（ms 粒度太粗），保证采样间隔严格 500µs，时间戳真实可信
波特率代码里硬改硬件 sdkconfig 是生成物，set-target 会重新生成并冲掉手工修改；uart_set_baudrate 直接写硬件寄存器，不依赖驱动安装，谁也冲不掉

3. 上位机关键代码（PyQt6 + pyqtgraph，单文件 scope_app.py）

3.1 串口线程：SerialWorker（QThread）

设计要点：

  • 收数在 QThread，绘图在主线程——串口阻塞绝不卡 UI，中间靠 pyqtSignal 跨线程投递（Qt 自动排队，线程安全）。
  • 接收统计是排障神器：字节>0 且解析=0 → 波特率错（乱码）；字节=0 → 固件没跑；解析在涨 → 链路通。三行日志把”没数据”这种模糊故障切成三种确定状态。
  • 失败走 error 信号：打开串口失败时主线程复位按钮/标签并亮出错误文本，不让界面说谎（曾出现过”标签显示已连接实际打开失败”的误导）。

3.2 边沿测量：线性插值过阈检测

  • 用上升沿间隔的中位数求周期——单个异常沿不会污染读数。
  • 占空比 = 每个上升沿到下一个下降沿的中位时长 ÷ 周期。
  • 电平用 90/10 百分位而不是 max/min——抗毛刺。

3.3 边沿触发提取（波形稳定不漂的核心）

每次刷新都重新搜”最后一个满足窗口约束的上升沿”→ 波形始终以触发沿为 x=0 对齐 → 静止不漂。找不到边沿自动退化为滚动模式。

3.4 时基语义（示波器惯例）

缓冲区 BUF_SEC = 22s，必须 ≥ 最大时基（2s/格×10格）。

4. 踩坑全记录（当天实战，7 个坑）

# 现象 根因 修法
① 反复改波特率不生效 sdkconfig 是生成物，set-target 重新生成冲掉手工修改；sdkconfig.defaults 优先级又低于目标默认 代码里 uart_set_baudrate() 硬改硬件，绕过整个配置体系
② 打开 COM3 没有权限 Windows 串口独占：自己前一个实例 / idf.py monitor 还开着 找到旧窗口关掉；monitor 用 Ctrl+] 退出
③ connect_serial AttributeError __init__ 引用了不存在的方法（按钮走的 on_connect 没被复用） 命令行 --port 也走 on_connect() 统一路径
④ esp_timer.h: No such file main 组件一旦显式写 PRIV_REQUIRES，就失去自动依赖全部组件的特权 esp_driver_uart esp_adc esp_timer 三个都显式列上
⑤ 波形只有一条竖线 Y 轴锁死 (-0.25, 3.65)，而换算满量程 4.4V → 高电平 4.17V 被裁在屏幕外 Y 轴扩到 (-0.3, 4.8)，两处口径必须一致
⑥ 一屏只有一个周期 时基值被当成”全屏宽度”，示波器惯例是每格宽度（×10 格） window = 档位值 × 10；缓冲扩到 22s
⑦ 轴标 18ms 实际是 18 秒 数据单位是秒，轴标签却写 units='ms'，pyqtgraph 按标签口径显示 units='s'（pyqtgraph 会按视窗自动切 ms 前缀）

另外两个通用陷阱：

  • np.min(arr, initial=np.nan) NaN 传播：数组非空也返回 nan，占空比永远算不出来 → 显式判空。
  • pyqtgraph 0.14 移除了 enableMenu：升级后旧 API 直接 AttributeError，删掉即可（右键导出菜单反而有用）。

5. 当天实测结论

项 数值 意义
采样率 1973~1997 /s 目标 2000Hz，printf 开销占用 ~1.3%，达标
NE555 高电平 raw ≈ 3877（显示 4.17V，实际引脚 ≈3.0V） 模块 OUT 直出 12V（无内置 7805）——高压区验源判据按此定
NE555 低电平 raw ≈ 2（0.001V） 分压链干净
当前模块频率 ~1.8Hz（电位器在最低频端） 待拧到 100Hz/50Hz

遗留：① 电位器拧到 100Hz/50Hz 后复测记录；② 该模块频率范围下限太低，如果拧到头仍达不到 100Hz，需并电容改定时网络。

第 12 步：发布到 GitHub Pages

12.1 网页上建仓库

打开 https://github.com/new，填仓库名（例如 ai-agent），选 Public，「Add a README」「Add .gitignore」「Choose a license」三项一个都别勾。

为什么别勾：勾了远端会自带一个初始提交，和你本地的第一次提交没有共同祖先，第一次 push 必然被拒，还得硬合。空仓库最干净。

12.2 源码和产物分两个分支

这是新手最容易搞乱的地方，记住一句话：main 放你写的 md，gh-pages 放 Hexo 生成的 html。

然后把 public/ 单独推到 gh-pages（用一个临时目录，避免切分支时动到源码）：

推完 gh-pages 分支，GitHub 通常会自动启用 Pages（在仓库 Settings → Pages 里能看到 Source 是 Deploy from a branch / gh-pages / (root)；没自动启用就手动选一下）。

为什么 -f 强制推：每次都是全新的孤立提交，和远端没有共同祖先。这是产物分支，本来就是「public/ 的完整镜像」，覆盖是预期行为。只对 gh-pages 用，别对 main 用。

第 13 步：日常维护与常见错误

现象 原因 怎么修
hexo generate 只打印帮助、不报错 package.json 少了 "hexo" 字段 补回该字段
Author identity unknown 没配 user.name / user.email 在仓库里配两条 git config
non-fast-forward / push 被拒 建仓库时勾了 README，或忘加 -f 推产物分支 空仓库重来；只对 gh-pages 用 -f
页面没样式、CSS 404 _config.yml 少 root: /仓库名/ 补上重新生成
突然要求输密码/令牌 SSH 地址被 insteadOf 规则改写成 HTTPS 用 ssh://git@ssh.github.com:443/... 形式，不匹配该规则
命令行粘贴令牌没反应 输密码时屏幕本就不回显 照常粘贴回车即可
改了文章，网页没变 没跑 clean + generate，或没重新推 gh-pages 跑一遍发布脚本
提交成功但页面 404 Pages 还在构建 等，别重复发布
网页上直接改的 HTML 被冲掉 产物分支是 public/ 的镜像，全量覆盖 改 source/_posts/ 里的 md，重新发布

术语速查

词 大白话
front-matter 文章开头 --- 包住的几行元数据（标题、日期、分类、标签）
YAML 一种「键: 值」的填表格式，front-matter 和 _config.yml 都用它
产物 / public/ Hexo 生成的那一堆 HTML、CSS、JS
分支 同一仓库里并行的两份内容；这里 main 存源码、gh-pages 存产物
Pages GitHub 把某个分支当静态网站发布出来的功能
PAT / 令牌 网站密码的替代品，HTTPS 方式推代码时要用；本流程走 SSH 密钥，用不上
.nojekyll 一个空文件，告诉 Pages「别用 Jekyll 加工，原样发」

完成检查清单

  • node/npm/python/git 都能打印版本号
  • ~/.workbuddy/skills/xxx/SKILL.md 有 name / description / agent_created
  • description 写的是「用户会怎么说」
  • 示例文件已删
  • 脚本在临时目录跑通，生成的文件开头是 ---
  • 重复运行会拒绝覆盖、路径穿越会被拦
  • 打包校验通过，拿到 zip
  • 用 Skill 生成了一篇真实文章
  • hexo generate 输出里有 generated
  • public/ 里有 index.html 和 .nojekyll
  • main 和 gh-pages 都推上去了
  • 网址返回 200，且页面里能搜到文章标题

一句话收尾：Skill 只是一个带说明书的文件夹；Hexo 只负责把 md 变 HTML；GitHub Pages 只负责把 HTML 发出去。 把这三件事分开，哪一步出错就查哪一步，不用整条链路重来。

Git 登录与 Hexo 博文自动发布

背景

本次会话先排查了「下载 Git 之后如何登录」，随后开发了一个把本地对话内容发布成 Hexo 博文、并可同步到 WorkBuddy 在线空间的 skill。这里把两段结论沉淀成一篇可发布的笔记。

结论：Git 本身不需要登录

Git 是装在电脑上的本地版本控制软件，没有账号体系。日常说的「登录 Git」其实混了三件事：

事项 在哪做 说明
配置提交署名 本地命令行 user.name / user.email，只是给 commit 盖作者章
注册并登录网站 浏览器 GitHub / Gitee 等托管平台的账号
建立认证凭证 本地 + 网站设置 SSH 密钥或个人访问令牌，这一步才叫「让 Git 能推拉」

本机实测结果：Git 2.55.0.windows.3 已装好，~/.ssh/id_ed25519 已存在，ssh -T git@github.com 返回 Hi cuishili-git! You've successfully authenticated —— 认证通道早就通了，账号是 cuishili-git。唯一缺的是提交署名。

还有一条容易忽略的全局配置：

它会把 git@github.com: 开头的 SSH 地址强行改写成 https://github.com/。后果是以为在用 SSH 密钥，实际走 HTTPS，然后莫名弹出要密码或报认证失败。若目标是走 SSH，建议清掉；若本来就用 HTTPS + 令牌，留着也行，但要明白它改写了地址。

操作步骤

  1. 补齐署名，邮箱用平台账号绑定的那个，否则贡献统计和头像对不上：

  2. 认证优先 SSH：ssh-keygen -t ed25519 -C "邮箱"，把 .pub 内容粘到平台 SSH Keys 设置，再用 ssh -T 验证。

  3. HTTPS 路线必须生成个人访问令牌（PAT），主流平台已不接受账号密码；令牌只显示一次，要立刻存好。

坑与权衡

坑 处理
输密码/令牌时屏幕不回显 正常行为，照常粘贴回车
改过令牌仍报错 Windows 凭据管理器里删掉旧的 git:https://... 条目
公司网络封 22 端口 ~/.ssh/config 配 ssh.github.com:443，别急着换回 HTTPS

Hexo 发布 skill 的设计要点

  • 直接写 front-matter + 正文到 source/_posts，不调用 hexo new，因为后者不接受自定义子目录和多级分类；
  • 标题含冒号或引号时用 JSON.stringify 生成 YAML 双引号字符串，零依赖解决转义；
  • 默认只落盘，构建 / 部署 / 推送 / 在线上传都要显式开关，部署与推送还要求 --confirm-* 二次确认；
  • 同步到 WorkBuddy 在线空间前要剥掉 Hexo front-matter，否则在线文档里会显示成一段原始 YAML 文本；
  • Windows 下 npx.cmd --no-install hexo version 会挂住不返回，已从命令探测链中移除，并给所有探测加了超时。
